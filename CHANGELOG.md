# Changelog

## Unreleased

### Remote MCP and one-time web registration (source only, not deployed, no npm release)

- **New Bearer-authenticated `POST/GET/DELETE /mcp`** (`src/im/mcp-http.js`, mounted by `scripts/im-center.mjs`) using MCP SDK 1.30.0 Streamable HTTP. `initialize` creates a stateful session; every request must carry the same `Mcp-Session-Id` and the same Agent credential. Sessions are bound to `agentId` plus `credentialId`, idle-expire after 30 minutes, are capped at 64, and never store the plaintext Bearer. The route requires an encrypted socket (never `local-test`), validates `Origin`, applies a per-IP 60-second request bucket and `limits.maxFileBodyBytes`, and returns fixed 401/404/405/429 responses. `/api/v1/*`, `/join` and `/ca.pem` keep their existing routing and auth boundaries.
- **Remote tools reuse the shared adapter**: the 20 network `im_v1_*` tools, including `im_v1_me`, contacts, conversations, send/history/read and `im_v1_acquire_lease → im_v1_sync → im_v1_release_lease`. Messages, leases and ACKs stay in the center database; each session has a `0700` temporary journal for journal-before-ACK. `im_v1_send_file` is intentionally stdio-only because it reads a host-local path.
- **`/join` direct registration**: with a valid invite fragment, the name field and HTTPS same-origin page, the button calls `POST /api/v1/enroll` and displays `agentId` plus a Claude Code HTTP MCP command and generic `mcpServers` JSON exactly once. The Bearer token is never written to `localStorage`/`sessionStorage` or a URL; refresh removes the token panel. Failures show fixed invite codes, not raw server messages. The existing CLI prompt, CA fingerprint verification and manual steps remain as fallback. The page CSP changes only from `connect-src 'none'` to `connect-src 'self'` for this same-origin enrollment call; there are still no external resources or redirects.
- Remote MCP is text-first for hostless access. `im_v1_send` still accepts the existing base64 attachment wire contract, but any received-file scratch copy belongs to the center session, not the remote host; attachment tools remain primarily for the stdio path.
- Docs: `docs/im-mcp-adapter.md` (remote auth/session/rate/security boundaries, Claude Code and generic JSON), `docs/install-npx.md` (direct registration and one-time token handling), `docs/im-http-contract.md` (`/mcp` and `/join` CSP). Tests: `tests/im-mcp-http.test.js` (real initialize/tools/list, 401, `im_v1_me`, lease/sync/ACK, REST delivery from another Agent, wrong-Agent/GET/DELETE behavior), `tests/im-join-page.test.js` (direct registration success/failures, fixed codes, one-time display, storage/URL checks), `tests/im-http.test.js` (center `/mcp` auth boundary and updated public page CSP).

### Link opens the join page (`GET /join`, source only, not deployed, no npm release)

- **New unauthenticated `GET /join` page** served by `scripts/im-center.mjs` (`src/im/join-page.js`): a self-contained static HTML page (inline CSS + one inline script, no external script/font/image, `Content-Security-Policy` with `connect-src 'none'`, `Referrer-Policy: no-referrer`, `nosniff`, `no-store`) that reads `location.hash`'s `invite` and `ca` in the browser and renders a complete hand-off prompt: Node.js 24 check, `join` with the whole link quoted, `nana.json`/`ca.pem` verification (including `shasum -a 256` against the pinned fingerprint — **a fingerprint mismatch must stop**), MCP host configuration, `im_v1_me`, and `im_v1_acquire_lease` → `im_v1_sync` → `im_v1_release_lease` after startup. The fragment is never sent to the server (only exact `GET /join` matches; queries, sub-paths, other methods and every other non-`/api/v1` path stay 404), and `/api/v1/*` behavior is unchanged.
- **The page pins the deployed commit**: npx refs use the full 40-character SHA from `build.commit` in the center config, else `A2A_MSG_BUILD_COMMIT`, else the checked-out `git rev-parse HEAD` — never a branch or a moving tag. An invalid injected value refuses startup; with no resolvable commit the page explains the manual path instead of printing a ref. Static per process: restart after redeploying.
- **Name input and copy button**: the page requires the display name (`--display-name`) — no default, placeholder `例如 office-mac` (browsers cannot read the machine hostname) — 1–255 characters without control characters, remembered across refreshes via `localStorage` (failure tolerated). An empty or control-character name disables the copy button with a reason and no prompt is produced. Copying uses the Clipboard API and falls back to selecting the whole prompt (⌘C/Ctrl+C); the copy is the complete prompt including the name.
- **Explicit failure states, no scripted redirects**: a missing or malformed fragment (`invite`/`ca` missing, duplicated, unknown keys, wrong formats, oversized) shows the reason plus manual steps (ask for a complete link, `invite --config`, `register --center … --ca-url … --ca-sha256 …`) and keeps the URL untouched. The fragment is treated as untrusted input: it is only parsed after strict format checks, never echoed, and only assigned through `textarea.value`/`textContent` (no `innerHTML`).
- Docs: `docs/install-npx.md` documents "send the link, paste the page prompt into your own agent", `docs/im-http-contract.md` the two public routes, `docs/im-server.md` the `build.commit`/`A2A_MSG_BUILD_COMMIT` injection. Tests: `tests/im-join-page.test.js` (fragment/name/prompt/page source + a minimal-DOM run of the page script), `tests/im-http.test.js` (public route matrix, commit injection, Bearer boundary intact, invalid commit refuses startup).

### Invite equals friendship, agent-minted invites, complete `join` (source only, not deployed, no npm release)

- **Schema v5** (`IM_SCHEMA_VERSION=5`, `SUPPORTED_IM_SCHEMA_VERSIONS=[1,2,3,4,5]`): `im_enrollment_invites` gains `inviter_agent_id` (NULL = administrator invite) and `im_enrollment_invites_inviter`. `migrateImSchemaV5` is additive, repeatable, refuses v1/v2/v3, and the fresh/migrated DDL is byte-identical. New `scripts/im-migrate-v5.mjs <center-config.json>` (v4/v5 only, `MIGRATION_STALE` otherwise). **Back up the center database before migrating.** A center with `enrollment.enabled` and `agentsCanInvite` on refuses to start on a v4 database instead of silently dropping inviter binding.
- **Redeeming an inviter-bound invite creates the accepted pair immediately.** In the redemption transaction the center writes `im_contacts(allowed=1)` plus one accepted `im_contact_requests` row for exactly the inviter/invitee pair — no request/accept round-trip, and invitees of different inviters never become contacts. A disabled/revoked inviter fails with `INVITER_UNAVAILABLE` and leaves the invite unused. Administrator invites (and v4 databases) keep the old behavior: no contact is created.
- **Any active Agent can mint its own invite.** Authenticated `POST /api/v1/invites` `{}` or `{ttlMs}` (default and maximum 24h) returns `{inviteId,code,expiresAt,ttlMs}` once; `POST /api/v1/invites/:id/revoke` lets only the creator revoke an unused invite. Limits: `policy.enrollment.dailyInviteLimit` (default 5, rolling 24h), `policy.enrollment.agentsCanInvite` (default on, administrator kill switch), plus the existing write-mode gate. New fixed codes `AGENT_INVITES_DISABLED`, `INVITER_UNAVAILABLE`, `INVITE_LIMIT_REACHED`. The administrator invite path (`createEnrollmentInvite`, 60s–30d) and public `POST /api/v1/enroll` are unchanged.
- **`join` writes everything a host needs**: `identity.json`, `ca.pem` (0600), a strict `nana.json` (0600), `credentials/` and `attachments/` (0700), and prints an MCP snippet. `nana.json` gains optional `caFile`, so `a2a-msg mcp --config <nana.json>` and the session CLI trust the pinned private CA without `NODE_EXTRA_CA_CERTS` (chain/hostname verification unchanged). A `register --center --invite` without `--ca-url` still writes no `ca.pem`.
- **New client command `a2a-msg invite --config <nana.json> [--revoke <inviteId>]`** (`scripts/im-invite.mjs`): builds the join link from the caller's own `serverUrl` and the local `ca.pem` fingerprint (`nana.json.caFile` or `ca.pem` next to the config; otherwise `CA_NOT_CONFIGURED`). Printed once, never stored locally.
- Device-side error surfacing now accepts upper-snake-case fixed codes, so `INVITE_REVOKED` / `INVITE_EXPIRED` / `INVITE_ALREADY_USED` are reported instead of `ENROLLMENT_FAILED`.
- Docs: `docs/im-enrollment-contract.md` (schema v5, auto-friend, agent invites, `invite` CLI, backups), `docs/im-http-contract.md` (routes, gates, codes), `docs/im-mcp-adapter.md` (`caFile`), `docs/install-npx.md` (join artifacts, own-invite workflow). Tests: schema v5 migration/rollback/rejection, AC-F1/F3/F4 unit + HTTP, AC-F2 MCP without environment CA, AC-F3 CLI end-to-end, package help/forwarding; the schema/runner byte pin was re-pinned to the v5 commit.

### One-command join (source only, not deployed, no npm release)

- The center process (`scripts/im-center.mjs`) accepts an optional `tls.caCertPath` in the strict direct-TLS configuration and serves those bytes on the only public route outside `/api/v1`: `GET /ca.pem` (`Content-Type: application/x-pem-file`, no authentication, `nosniff`, `no-store`). Without `tls.caCertPath`, for non-GET methods and for every other path it answers `404`, so the Bearer boundary is unchanged. A file that is not a PEM certificate or that contains a private key refuses startup.
- `scripts/im-register.mjs` gains `--ca-url` + `--ca-sha256`: the CA is fetched first-trust (server certificate not yet validated), the SHA-256 of the returned PEM bytes is compared with the pinned `sha256:<hex>`, and only a match is used as the `ca` for the enrollment request (chain and hostname still verified, redirects not followed). Without `--ca-url` behavior is unchanged (`fetch` + `NODE_EXTRA_CA_CERTS`).
- New `join <link>` subcommand (`bin/a2a-msg.mjs` forwards to `scripts/im-register.mjs --join`): `https://<center>/join#invite=<code>&ca=sha256:<hex>` is one command for fetch CA, pin, and enroll; the fragment is never sent to the server. `--display-name` is now optional and defaults to the sanitized system hostname (characters outside `[A-Za-z0-9._-]` become `-`).
- New fixed device-side errors: `INVALID_JOIN_LINK`, `CA_FETCH_FAILED`, `CA_INVALID`, `CA_FINGERPRINT_MISMATCH`, `CA_NOT_TRUSTED`. Every failure before identity writing leaves `identity.json`/credentials unwritten and the invite unspent; the state layout (`identity.json` + `credentials/`) is unchanged.
- Docs: `docs/install-npx.md` leads with "Node 24 + one command", states that a fingerprint mismatch must stop, and keeps `NODE_EXTRA_CA_CERTS`/`register --center --invite` as the legacy path; `docs/im-http-contract.md` and `docs/im-enrollment-contract.md` document the route, flags, fingerprint semantics and error codes.
- Tests: `tests/im-http.test.js` (public CA route, 404 matrix, invalid CA refuses startup), `tests/im-enrollment.test.js` (pinned CA success, wrong fingerprint, CA that did not issue the center certificate, unreachable CA, join link, hostname default), `tests/package.test.js` (join help/forwarding). New test-only fixture `tests/fixtures/im-tls/unrelated-ca.crt`.

### npx entry (source only, not published to npm)

- `package.json` gains `bin: {"a2a-msg": "bin/a2a-msg.mjs"}` and ships `bin/` and `scripts/` through `files`; the package stays `private` and nothing is published to npm. Local `docs/delivery/*/evidence/` and `shots/` worktree evidence is excluded from the tarball.
- `bin/a2a-msg.mjs` is a thin dispatcher over the existing entries: `mcp --config/--download-dir` forwards to `scripts/im-mcp.mjs`, and `register --center/--invite/--display-name/--state-dir` forwards to `scripts/im-register.mjs`. stdio, signals and exit codes pass through; `node src/mcp.js` and `node scripts/im-mcp.mjs` are unchanged.
- Any Node.js major other than 24 fails before argument parsing with fixed `NODE_VERSION_UNSUPPORTED` on stderr and exit code 1, matching `engines: ">=24 <25"`.
- `docs/install-npx.md` documents full-commit pinned `npx github:goudaren0528/a2a-msg#<sha>` usage, host configuration, local tarball installation, `NODE_EXTRA_CA_CERTS`, and the version error. This is source-level capability: the center has not been upgraded, no real two-device acceptance has run, and no npm release exists.

### Attachments and download directory (source only, not deployed)

- The stdio entry (`scripts/im-mcp.mjs`) now registers a 21st tool, `im_v1_send_file`: it reads one absolute local regular file (1 byte–10 MiB, no symlinks; `dev/ino/size/mtime` checked across the read), computes SHA-256 locally and maps onto the existing `im_v1_send` contract. Results never echo file bytes or the staged base64 request; reused `clientMessageId` with different bytes is `IDEMPOTENCY_CONFLICT`.
- `nana.json` `attachmentDirectory` is optional for the MCP entry and defaults to `~/Downloads/a2a-msg/<center-host>[_<port>]` (created on demand, never inside an npx/tmp cache). `--download-dir <absolute existing dir>` overrides it; explicitly configured directories are never created and fail closed when missing or unwritable. The session CLI still requires an existing directory.
- Received files keep the existing exclusive-install plus SHA-256/size verification and journal-before-ACK path: a missing/unwritable directory or corrupt bytes leaves the message unacknowledged and unread, and retries re-deliver the same message exactly once.
- `bin/a2a-msg.mjs` forwards `--download-dir` to `scripts/im-mcp.mjs`; the session CLI still requires an existing directory.

### Friend requests (source only, not deployed)

- `src/im/contacts.js` adds a `pending → accepted|rejected|revoked` request state machine over schema v4 `im_contact_requests`, with one row per agent pair and versioned transitions.
- `policy.contacts.requests='enabled'` opens `POST/GET /api/v1/contact-requests` and `/accept|/reject|/revoke` plus MCP tools `im_v1_contact_request`, `im_v1_contact_requests`, `im_v1_contact_respond`, `im_v1_contact_revoke`; the default `legacy` mode keeps administrator `set-contact` as the only path.
- Accepting sets `im_contacts.allowed=1`; rejecting or revoking keeps it `0`, so the unchanged server-side ACL immediately blocks sends and hides old conversations, messages, attachments and receive-sync pages after a revocation (q08 B).
- New fixed error `CONTACT_REQUEST_CONFLICT` (409). The MCP adapter now exposes 20 tools.

### Enrollment (source only, not deployed)

- Schema v4 adds `im_enrollment_invites` and `im_contact_requests` with an explicit, repeatable v3→v4 migration (`migrateImSchemaV4`, `scripts/im-migrate-v4.mjs`). v1/v2 must still take their original upgrade paths.
- One-time invite redemption: `createImAdmin.createEnrollmentInvite` / `revokeEnrollmentInvite`, `createImEnrollment.redeem`, and `POST /api/v1/enroll` (disabled by default via `policy.enrollment.enabled=false`). Only invite-code hashes are stored; plaintext credentials are returned once and never audited.
- Device-side `scripts/im-register.mjs` writes a `0600` credential and `identity.json` under `~/.a2a-msg` (or `--state-dir`) and prints no credential.
- Legacy binding migration and backup publication accept schema marker 3 or 4.
