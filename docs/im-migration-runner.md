# Local IM migration runner (trusted isolated composition; not a production rollout)

`createTrustedMigrationServices({ db, dir, authority, approvalAuthority, actorId?, clock?, approvalTtlMs? })` returns frozen `{ publisher, registry, runner }`. The Unix-only native registry requires pre-existing protected `dir` and `dir/artifacts`, a file-backed **v3** SQLite database with initialized `im_instance_identity`, enabled foreign keys and safe synchronous durability. Upgrade a valid v2 database explicitly with `migrateImSchemaV3(db)` before constructing the runner, and publish a **new v3 backup** afterward; `migrateImSchema(db)` intentionally still creates/upgrades to v2 and does not automatically upgrade to v3. Historical v1/v2 database schema and structural backup support remain separate from this strict v3 publisher/runner gate. The factory rejects unrecognized options, including `platform`, `writer`, `resolver`, `backup`, `sourceId`, `fault` and `timeGuard`: no production test injection switch exists. The lower-level `createImMigrationRunner` is trusted in-process wiring for isolated tests/internals, not an untrusted user configuration endpoint.

The administrator authority must return synchronous literal `true` from `authorizeAdmin(context)` and supply trusted `publicationActors(context)` for backup publication. `await runner.createBackup({ approvalId }, context)` delegates only to the trusted publisher (`{ adminContext: context, approvalId }`); alternatively call `publisher.publish({ adminContext: context, approvalId })`. A backup-publication `approvalId` is **not** migration approval. Backup bootstrap for a structural v2 database before identity initialization is a separate operation; this migration runner strictly rejects missing identity.

After publication, `runner.preview(bindings, { backupId }, context)` authenticates first, obtains the real live DB identity and full schema validation outside any transaction, and uses `registry.withDiscoveredBackup` to verify protected publication, artifact/manifest hashes, real copy integrity, foreign keys, schema and identity under the coordinator lock. No publisher-return hashes need be retained. It returns `{ package, planHash }`; the package includes v2 tool/plan versions, actor, `instanceId`, `instanceCreatedAt`, numeric `registrationGeneration: 1`, schema version/checksum, preview ID/fingerprint, complete sorted member→agent bindings, backup ID, file and manifest hashes, operation, expected impact, and exclusive expiry. `planHash` hashes JSON serialization of that canonical package. Caller paths, source IDs, v1 packages, unknown keys and string generations are rejected.

An independent trusted migration approval authority must approve exactly `{ approver, planHash, backupId }` after review of the *entire* package. `runner.commit({ package, planHash, approval }, context)` reauthenticates and rechecks this independent approval. It requires all approved evidence including `manifestHash`; under one registry coordinator scope it physically re-verifies the controlled copy on **every** commit, then uses one `runWriteFresh` live transaction. Within that transaction, only point checks of DB identity, schema marker/checksum and captured schema cookie, registry metadata-only `recheck()`, admin/approval rechecks, canonical binding fingerprint and fresh expiration checks run; there is no backup hash/open or full schema/FK scan there. Registry lock precedes live write lock. Completion writes only bindings, a run, and metadata-only audit. A business failure may persist the clock floor without committing bindings. `now < expiresAt` is required after authorization/canonical checks and once more before returning from the write callback.

An exact approved retry after an uncertain COMMIT/release outcome returns the existing completed result, without duplicate bindings/run/audit, **only while the independent migration approval remains valid, the plan is unexpired and the backup remains verifiable and unrevoked**. The runner rechecks the identified audit row by primary key under the live write transaction; audit discovery outside that transaction is never sufficient alone. A final **complete** target-run binding rowset check after the last clock refresh uses the explicit v3 `im_legacy_bindings_run` index, bounded to approved count plus one. It refuses extra rows (including revoked rows), missing rows and changed mappings on first commit and exact retry; it does not assume SQLite row order matches JavaScript Unicode sorting. Never delete accepted rows or restore an earlier snapshot to compensate. Later messages do not stale a mapping. Legacy recipient permissions, `read_at`, old replies/attachments, IM credentials, send keys, deliveries, ACK and lease state, and write mode are not promoted or rewritten. Pause the separately integrated IM write mode if necessary while preserving accepted data; this module does not activate services or physically purge anything.

Preview computes `expiresAt` using a validated clock reading but does **not** commit a durable clock observation. Commit does not treat a preflight clock reading as an authoritative expiry decision: its exclusive deadline is checked against the shared clock guard's refreshed, durably observed time inside `runWriteFresh`, including after writes. An expired business attempt may commit only the clock floor; a later rollback of wall time below that floor is rejected even on a reopened connection.

**Limitation:** The registry coordinator serializes backup revocation and verified use, **not** arbitrary external approval-authority revocation. `authorizeApproval` is called before verification and again at the live transaction boundary; without an independently designed coordinated cross-process approval-use adapter this does not guarantee atomicity against revocation by an external process. That guarantee and restore rehearsal remain unsupported; this is not a production gate, deployment recipe or recovery claim.
