# Local IM migration runner (isolated; not a production rollout)

`createImMigrationRunner({ db, authority, approvalAuthority, provenanceResolver, backup?, sourceId, actorId?, clock?, approvalTtlMs?, fault?, probe? })` operates on an already-migrated **file-backed** local SQLite database. No HTTP interface, deployment, legacy-message copy, write-mode activation, restore, or destructive down migration is included. Protect the local database, backup destination, manifest, and approval authority independently. `probe` is only an observation hook for isolated tests; do not supply an untrusted hook.

Workflow: inject a trusted `authority.authorizeAdmin(context)` (for example `createAdminAuthority({ secretFile })`, with `context.adminSecret` supplied **out of band**, never as a CLI argument or in an approval package). Only synchronous literal `true` grants access. Preflight the v1 schema and proposed identities; call `await runner.createBackup({ destinationPath, approvalId }, context)` (or supply a real `createImBackup({ db, authority })` result configured for the platform). Runner passes the authenticated `context` unchanged as `adminContext` in `backup.backup({ destinationPath, approvalId, sourceId, adminContext })`. `approvalId` and `sourceId` are metadata, **not authentication**. `runner.preview(bindings, { backupPath, manifestPath }, context)` verifies the backup and returns `{ package, planHash }`. Human review must cover every member→agent mapping and the **entire** package. A separate trusted approval store/authority must record exactly `{ approver, planHash, backupId }` and implement `authorizeApproval(approval, context)` returning literal `true` only for that independently approved record. The returned approval is not a bearer string: a caller-provided digest or `admin:true` cannot approve itself. Commit with `runner.commit({ package, planHash, approval, backup: { backupPath, manifestPath } }, context)`; it reauthenticates, verifies physical backup evidence outside the write lock, then checks approval, provenance, expiration, mapping fingerprint and canonical plan under an immediate SQLite transaction. Verify completed bindings and audit after commit.

Canonical package fields: `toolVersion`, `planVersion`, `actorId`, `schemaVersion`, `schemaChecksum`, `sourceId`, `sourceInstance` (hash of the local DB path; no path disclosed), `previewId`, `sourceFingerprint`, the complete sorted `proposedBindings`, `backupId`, `fileHash`, `operation`, `expectedImpact`, and `expiresAt`. `planHash` is SHA-256 of JSON serialization of this canonical package. An expired, changed, unapproved, or stale package is rejected. The backup must pass the real backup service's `verify()` with `ok === true`; its manifest source, schema checksum, ID, and hash are checked against the package and current source. Backups are snapshots and **not** instructions to replace the live DB.

`provenanceResolver.resolve({ sourceId, sourceInstance, backupId, fileHash, schemaVersion, schemaChecksum }, context)` must be synchronous and trusted, retrieving an independently protected registration, not trusting the caller's manifest/package. It must return `{ registered: true, publicationState: 'published', revoked: false, registrationGeneration, sourceId, sourceInstance, backupId, fileHash, schemaVersion, schemaChecksum }` with matching values. Runner checks registration both outside and inside the write lock, including stable registration generation. Missing resolver yields `MIGRATION_PROVENANCE_REQUIRED`; missing, revoked, unpublished or mismatching registration yields `MIGRATION_PROVENANCE_REJECTED`, without committing. At commit time `now < expiresAt` is mandatory; equality already expires. Whole-file hashing, integrity/FK and schema inspection occur **outside** the live DB write lock; inside it the checks are bounded to current path-based identity, schema checksum, admin/approval/provenance status, fresh time and the proposed mapping's canonical plan/fingerprint. This does not establish cross-process registration/approval serialization.

**C is NOT a production migration gate.** Real protected registration and durable DB instance identity (including registration generation) are unfinished and belong to the subsequent schema subpackage (package 4 foundation); the present `sourceInstance` is only a hash of the DB path, not a durable instance identity. The tests' in-memory `provenanceResolver` is explicitly a **test double**, only for controlled unit-environment flow verification. Known unfinished items: no schema change or instance identity table; no reuse of `migration.js` guards (C-P1-2 nested-transaction avoidance is deferred to the provenance subpackage); no cross-process serialization of approval revocation. Do not deploy or treat successful tests as production-readiness evidence.

Commit writes only the reviewed legacy bindings, one completed run, and metadata-only audit with plan hash, backup ID and approver. It does not change legacy sender permissions, `read_at`, reply rights, IM message/ACK/key records or IM write mode. Later accepted legacy/IM messages do not stale valid bindings. A write failure rolls back that transaction, never restores a prior snapshot; an exact approved retry after a lost response returns the completed result without writing another batch. To roll back the application, stop the new protocol (and separately pause IM write mode if integrated), retain the upgraded database and all accepted messages. Recovery rehearsal, real disaster recovery, incremental restore, and RPO=0 are **not** provided or promised.
