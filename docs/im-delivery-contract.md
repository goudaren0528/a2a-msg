# IM receiver delivery (v0.2)

`createImDelivery({db,auth,acl,clock=Date.now,policy})` asserts the migrated IM schema once, requires the existing branded-principal auth and contact ACL interfaces, parses the policy with `parseImConfig`, snapshots it, and returns synchronous `{acquire,renew,release,sync,ack}`. No listener, legacy integration, token logging, or remote API is installed. Inputs are plain objects with only documented fields; IDs are lowercase UUID-shaped strings, sequence/generation/time values are safe integers. Errors are `ImError` codes from `contracts.js`.

* `acquire(principal,{instanceId,requestId})` returns `{instanceId,generation,expiresAt,historical}`. New acquisitions return `historical:false`; `(agentId,requestId)` persists the original response and a SHA-256 fingerprint of `[instanceId,credentialId]`. Exact retries return its original `instanceId`, generation and expiry with `historical:true` (including after release, expiry, restart or admin takeover), never a renewed capability. **A historical response is not proof of a currently usable lease:** renew, sync and ACK must still check the active fence. Mismatched fingerprints yield `IDEMPOTENCY_CONFLICT`. A live lease, including one belonging to a subsequently revoked credential, yields `LEASE_CONFLICT` even for the same instance with another request ID. A rotated credential must wait for expiry or request explicit admin takeover; it cannot silently steal the old fence. Expired/released leases remain in the table and the next acquisition increments generation. The persisted generation is preserved across restarts and admin takeover. The lease TTL comes only from the explicit configured `lease.ttlMs`; timestamp overflow fails `CLOCK_UNSAFE`.
* `renew(principal,{instanceId,generation})` returns `{instanceId,generation,expiresAt}`; `release` returns `{instanceId,generation,released:true}`. Both require an unexpired lease owned by precisely the authenticated credential, instance, and generation. Mismatches yield `STALE_FENCE`, expiry yields `LEASE_EXPIRED`. Release expires the row at current observed time, not deletion. Renew cannot revive an expired row.
* `sync(principal,{instanceId,generation,after?,streamEpoch?,limit?})` returns `{streamEpoch,ackedThrough,items:[{seq,message}],pageAfter,hasMore}`. `after` defaults to persisted `acked_through`; limit defaults to 100 and must be 1–100. A supplied `after` may be at or behind `acked_through`, but not ahead (`INVALID_REQUEST`). Wrong epoch or `after < retained_floor - 1` yields `CURSOR_RESET_REQUIRED`. Sequences belong to the recipient's delivery stream, never global message IDs. Rows through the page plus one lookahead must be consecutive from `after+1` to the persisted `next_seq-1` watermark; missing middle or tail deliveries (including missing joined messages) yield `STORAGE_UNAVAILABLE`, never an empty/truncated page or an implicit ACK. A genuinely empty stream or complete final page succeeds; a valid retained floor follows the cursor-reset rule rather than being mistaken for corruption. Each message DTO contains `messageId,conversationId,senderAgentId,recipientAgentId,clientMessageId,title,text,inReplyTo,correlation,acceptedAt,attachment`; attachment is `null` or `{attachmentId,name,mime,size,sha256}`. Attachment bytes are never fetched or returned. Current conversation/contact ACL is checked for every returned message; an inaccessible pending message yields `SYNC_BLOCKED`, not a skipped item. Sync does not modify ACK or `read_at` and makes no durable receipt assertion. `pageAfter` is last returned sequence or requested `after` if no items; `hasMore` indicates additional delivery rows.
* `ack(principal,{instanceId,generation,messageIds})` accepts 1–100 unique lowercase UUIDs and returns `{ackedThrough}`. All IDs must correspond to **this recipient's** deliveries and remain accessible through current contact ACL. Validation and ACL checks precede writes; one invalid/foreign/inaccessible ID fails the complete transaction. First ACK stamps `acked_at`; retries preserve the original timestamp. The cumulative cursor advances only across contiguous acknowledged delivery rows (out-of-order ACK leaves holes). ACK is the client's assertion of durable receipt, not server proof that bytes were saved. ACK does not set `read_at`; read marking belongs to a separate operation.

Every operation revalidates the branded, currently active principal. Mutations use a synchronous immediate SQLite transaction, observed monotonic IM clock and metadata-only audit entry in the same transaction; audit failure rolls back all changes. Sync uses `readImClock`, not a write transaction. Disabled config yields `IM_DISABLED`. **Both** the snapshotted config `writeMode` and persisted `im_settings.write_mode` must be enabled for acquire, renew, release and ACK; a pause rejects all four with `NEW_WRITES_DISABLED` (including cleanup release and replay), while a valid pre-existing lease may still sync read-only. This is a safety boundary, not a queue/purge/read-receipt mechanism. No IP address supplies receiver authority.
