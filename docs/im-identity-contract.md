# IM v1 identity, administration, and ACL contract

This is a library foundation, not an HTTP or OS authentication implementation. The caller supplies an already opened/migrated Node `DatabaseSync` with foreign keys enabled (schema v4 for enrollment; v1–v4 remain verifiable). Factories call `assertImSchema` once; per-request identity checks are indexed reads, not manifest scans. Admin bootstrap is permitted while `im_settings.write_mode='paused'`: the pause still gates ordinary message/receive writes elsewhere.

`createImAuth({db,clock=Date.now})` returns `{authenticate(rawCredential),assertActive(principal)}`. Raw credential is exactly `<lowercase-uuid>.<43-character unpadded base64url encoding of 32 random bytes>` (80 characters total). Issuance returns plaintext once; only SHA-256 of the **secret component** is persisted in `im_credentials.secret_hash`, never the plaintext. Validation performs constant-time digest comparison, rejects malformed or noncanonical encoding, and reports all missing, revoked, expired, disabled, or wrong-secret credentials as `INVALID_CREDENTIAL`. Expiration is exclusive (`expires_at <= now` invalid). No IP fallback or IP argument exists. Authentication returns a frozen `{agentId,credentialId}` principal branded by that auth factory's private WeakSet; callers pass the original reference through internal modules, never deserialize a principal from HTTP/JSON. `assertActive` rejects unbranded objects and rechecks database credential ownership, expiry, revocation, and agent status every call.

`createImAdmin({db,clock=Date.now,random=randomBytes,authorizeAdmin})` requires a synchronous, trusted authorization callback returning literal `true`; no callback fails closed (`POLICY_NOT_CONFIGURED`), other values deny (`OPERATION_FORBIDDEN`), and thenables are rejected. An HTTP caller's self-reported `{admin:true}` does not confer authority. This API does not supply OS authentication. Every operation authorizes before a `BEGIN IMMEDIATE` transaction, observes persisted monotonic time, changes rows and writes an `im_audit` record atomically. The `reason` field is required, 1–255 printable characters, never a body or secret; audit records use bounded IDs and safe details, never credentials. Inputs are exact objects with no unknown keys.

Optional trusted factory callback `protectCredential({credentialId,agentId,credential})` runs within issuance's DB transaction before inserting the credential row. It must synchronously protect/fsync generated material and return a synchronous cleanup function for its own artifact. Explicit async callbacks, async cleanup functions and thenable protection results cannot activate a credential. Transaction failure invokes cleanup; thrown or thenable cleanup results become `STORAGE_UNAVAILABLE` (with nonsecret `credentialId`) and require manual local-file inspection. Rejected thenables are observed to avoid unhandled rejections; a synchronous callback must **not** secretly start asynchronous side effects, whose external actions this library cannot undo or verify. Never expose this callback to HTTP/model-controlled input or log its argument. Existing callers without this factory callback retain their original behavior; local admin CLI supplies it to prevent activation before protection.

- `registerAgent({displayName},ctx)` -> `{agentId,displayName,status:'active',streamEpoch}`; UUID agent and epoch generated independently; receive state starts `next_seq=1,acked_through=0,retained_floor=1`. Historical IDs are never reassigned.
- `issueCredential({agentId,expiresAt},ctx)` -> `{credentialId,agentId,credential,expiresAt}`; `expiresAt` is a future safe integer millisecond timestamp or explicit `null`.
- `revokeCredential({credentialId,reason},ctx)` -> `{credentialId,revokedAt}`.
- `setAgentStatus({agentId,status,reason},ctx)` -> `{agentId,status}` (`active`/`disabled`).
- `setContact({agentA,agentB,allowed,reason},ctx)` -> `{agentLow,agentHigh,allowed,version}`; granting (`allowed:true`) requires both endpoints currently active, while denying (`allowed:false`) permits an existing disabled endpoint (but never missing or revoked). No self-contact; canonical sorted pair; one bidirectional policy with incrementing version. Revoking a relationship denies old v1 history immediately, and re-enabling an endpoint does not restore it.
- `takeoverReceiver({agentId,reason},ctx)` -> `{agentId,changed,generation}`; active lease increments generation and expires at `now`, leaving its row; absent/expired lease returns `changed:false` without inventing an owner (generation `null` when absent).
- `createEnrollmentInvite({ttlMs},ctx)` -> `{inviteId,code,expiresAt}`; `ttlMs` is 1 minute to 30 days. The 43-character unpadded base64url code is returned once; only its SHA-256 is stored, and audit details contain only the expiry.
- `revokeEnrollmentInvite({inviteId,reason},ctx)` -> `{inviteId,revokedAt}`; only an unused, unrevoked invite can be revoked.

`createImEnrollment({db,clock})` (schema v4 only) exposes `redeem({inviteCode,displayName})` -> `{agentId,displayName,credentialId,credential,expiresAt:null}`. Redemption is one atomic write: create the agent and receive state, issue a credential, mark the invite used, and append a `system/enrollment` audit row. The credential is returned once and is never audited or logged. Missing, used, revoked and expired invites return `INVITE_NOT_FOUND`, `INVITE_ALREADY_USED`, `INVITE_REVOKED` and `INVITE_EXPIRED` respectively; malformed input returns `INVALID_REQUEST`. See [enrollment contract](im-enrollment-contract.md).

`createImContacts({db,auth,clock,timeGuard,policy})` implements the friend-request state machine over `im_contact_requests` and is only usable when `policy.contacts.requests='enabled'`; with the default `legacy` mode every method returns `POLICY_NOT_CONFIGURED` and administrators keep the sole `set-contact` authority. It returns `request(principal,{peerAgentId})`, `respond(principal,{requestId,action:'accept'|'reject'})`, `revoke(principal,{requestId})` and `list(principal,{direction?,after?,limit?})`. Each unordered agent pair has at most one request row; `version` increments on every state change and `updated_at` drives the keyset cursor. `request` creates or reuses a `pending` row; when the other person already has a pending request, that second request is mutual consent and immediately becomes `accepted`. `respond` is target-only and only accepts `pending -> accepted|rejected`. `revoke` lets the requester cancel a pending request or either party end an accepted relationship; `accepted -> revoked` atomically sets `im_contacts.allowed=0` (incrementing its version), so the existing ACL immediately hides conversations, messages, attachments and receive-sync pages. Illegal transitions return `CONTACT_REQUEST_CONFLICT`; missing rows and non-participants are hidden as `RESOURCE_NOT_FOUND`. An administrator-granted contact without a request row is materialized as an accepted row on the next `request`, keeping the two representations consistent. Audit rows (`contact_request_sent|accepted|rejected`, `contact_revoked`) contain only request/agent IDs, status and version — never credentials or message content. The canonical `im_contacts.allowed=1` remains the ACL source of truth, so `requirePeer`, sending, history and sync need no separate client-trust check.

`createImAcl({db,auth})` returns `{requirePeer(principal,peerAgentId),requireConversation(principal,conversationId),requireMessage(principal,messageId),assertAttachmentAccess(principal,attachmentId),requireAttachment(principal,attachmentId)}`. All validate the branded, currently active principal. `requirePeer` returns frozen `{agentLow,agentHigh,peerAgentId}`. Conversation/message methods return their respective raw SQLite snake_case row. `assertAttachmentAccess` returns frozen safe attachment metadata `{attachment_id,message_id,name,mime,size,sha256}` without selecting `data`; it checks the parent message, conversation and current contact on every call. `requireAttachment` performs that same metadata authorization first, then fetches the BLOB once and returns the original full raw SQLite attachment row for existing callers. Unauthorized resources remain hidden as `RESOURCE_NOT_FOUND` without fetching attachment data. Both conversation members must be active and the shared contact must currently have `allowed=1`. Message sender and recipient must be the exact distinct conversation members; attachment inherits its parent message's ACL. Missing and unauthorized peer/resource IDs both yield `RESOURCE_NOT_FOUND`; invalid identity yields `INVALID_CREDENTIAL`. No legacy storage is read or modified. Reply-to same-conversation checks belong to the later message transaction.

`readImClock(db,clock)` returns a safe integer `now` only if it is at least persisted `im_clock.last_observed_at`, otherwise throws `CLOCK_UNSAFE`; it does not write or begin a transaction. `observeImClock(db,clock)` requires an active transaction, checks the same invariant and persists the new observation atomically. Consumers of lease or expiry decisions should use these helpers rather than raw time; admin writes use `observeImClock`, auth reads use `readImClock`.
