# IM messages library contract

`createImMessages({db,auth,acl,clock=Date.now,policy,onCommitted?})` requires an already migrated Node SQLite `DatabaseSync` with foreign keys enabled, the real `createImAuth` and `createImAcl` objects, and a complete `parseImConfig`-compatible policy. The factory validates and snapshots policy values; it returns a frozen object with synchronous methods. No HTTP routes, legacy reads, deployment, retention purge, or delivery lease protocol are provided here. The application must authorize administrative provisioning separately and must not treat project or IP as identity. Caller passes original, branded, currently valid auth principals; ACL checks current contact permission on all resource reads and writes.

Methods (all arguments are `(principal,input)` except `send(principal,rawMessageRequest)`):

- `ensureConversation({peerAgentId})` → `{conversationId,peerAgentId,createdAt}`; active bidirectional allowed contact, one canonical pair, existing pair returns same conversation.
- `listContacts({after?,limit?})` → `{items:[{peerAgentId,displayName}],nextCursor}`.
- `listConversations({after?,limit?})` → `{items:[{conversationId,peerAgentId,createdAt}],nextCursor}`.
- `send(rawMessageRequest)` → message DTO with `replayed:false` for a new commit and `replayed:true` for same-key/same-payload retry. The raw object is *always* passed through `normalizeMessageRequest` with configured attachment limit, and `fingerprintMessage` is recomputed internally. There is no pre-normalized/bytes bypass or sender field.
- `getSendResult({clientMessageId})` → same DTO plus `replayed:true` for a retained, live sender-owned key; unknown key is 404. Safe to call while writes are paused, e.g. after a lost send response. This is not a write or automatic resend.
- `listHistory({conversationId,after?,limit?})` → `{items:[message DTO],nextCursor}`. Ordered by `(acceptedAt,messageId)` for timestamp ties.
- `getMessage({messageId})` → message DTO. `getAttachment({attachmentId})` → `{attachmentId,name,mime,size,sha256,data:Buffer}` after byte length and digest recheck. HTTP adapters must impose safe content disposition/type and never treat metadata as trusted headers.
- `markRead({messageId})` → `{messageId,readAt,changed}`; only the actual recipient after delivery `acked_at` exists; repeat reads return the same timestamp with `changed:false`. ACK is owned by the independent delivery module; this library does not invent ACKs.

Message DTO shape: `{messageId,conversationId,senderAgentId,recipientAgentId,clientMessageId,title,text,inReplyTo,correlation,acceptedAt,deliveredAt,readAt,attachment}`; `attachment` is null or `{attachmentId,name,mime,size,sha256}`. No attachment data, raw credentials, or stored request bytes occur in message DTOs, audit, or notifications. `deliveredAt` reflects delivery ACK (`acked_at`), not delivery queue insertion. Missing/unauthorized resources are `RESOURCE_NOT_FOUND` without disclosing other conversations. Pagination `limit` defaults to 20 and must be integer 1..100. Opaque base64url cursors encode kind and principal scope (plus conversation for history); a cursor from another kind, principal or conversation fails `INVALID_REQUEST`. Contacts and conversations use stable UUID ascending keys and current contact/agent filters. Cursors are not cryptographic authorization tokens; each page checks branded identity and ACL anew. Concurrent additions may affect subsequent pages; no snapshot guarantee.

Enabled=false causes `IM_DISABLED`; read operations remain available under enabled+paused. New ensure/send/read writes require both the frozen policy's `writeMode:'enabled'` and persisted `im_settings.write_mode='enabled'` inside `BEGIN IMMEDIATE`; paused send **does not** replay and does not write. Every mutation rechecks auth and ACL inside its immediate transaction, observes persisted monotonic clock, audits atomically, and fully rolls back failure. Send writes message, optional single attachment, reserved sender/client key, recipient sequence delivery, receive state and safe-ID audit together. Sequence uses current `next_seq`, then increments it; failed writes consume no sequence. `retry_until = accepted_at + safeRetryWindowMs` with safe-integer overflow rejection. Same sender/client UUID and hash inside the window yields the original message ID; different hash yields `IDEMPOTENCY_CONFLICT`; `status='expired'` or `retry_until <= now` yields `IDEMPOTENCY_WINDOW_EXPIRED` without reusing the key. No physical TTL deletion/purge is implemented: retention periods are policy constraints only, **not enforced cleanup**. Production publication must gate on a separately implemented/reviewed retention cleanup that preserves reserved-key safety and semantics after cleanup. `getSendResult` likewise honors the retry deadline, not presumed physical retention.

Optional `onCommitted` receives only a frozen ID/category event (`kind:'conversation_created'|'message_sent'|'message_read'`, corresponding IDs), synchronously after successful commit. Throws (or promise rejection) are ignored; callbacks never execute inside the transaction or turn an accepted send into failure. No asynchronous work is awaited by transactions.
