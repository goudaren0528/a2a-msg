# IM SSE hints (not durable delivery)

`GET /api/v1/events` opens a read-only SSE stream under the same IM authentication and transport policy as other `/api/v1` routes. Send a canonical bearer credential **only** in `Authorization`; no query keys, extra headers, receiver proof, or request body are accepted. A successful response has `Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: no-store` and `X-Request-Id`. Failures before headers use the usual fixed safe IM JSON errors.

An authorized recipient may receive `event: change\ndata: sync\n\n` after a contact sends a newly committed message. No message body, title, attachment metadata/path, credential, ID, sequence, epoch or watermark is transmitted. Comment frames (`: heartbeat`) are keepalive only. Notifications are best effort: a lost frame, no connected subscriber, stream closure, center restart or out-of-order hint changes no durable state. Always obtain a receive lease and use `/sync` with the per-recipient receive sequence and contiguous `/acks` for reliable recovery. SSE does not grant a receive lease, ACK, delivered status or read status.

Subscriptions are in-memory, capped at 2 per agent and 100 globally (hard configuration ceilings 10 and 1000). An over-cap connection returns `RATE_LIMITED` (429). Trusted defaults: heartbeat/credential-and-contact recheck every 15 seconds, idle stream closure at 120 seconds; ceilings are 30 seconds and 300 seconds respectively. Revoked credentials/contacts terminate existing streams on recheck, and a send rechecks authorization before writing its hint. A stream's fixed lifetime requires the client to reconnect and sync. Slow consumers are disconnected rather than buffered. The 30-second ordinary HTTP request timeout does not apply to this route; close/idle/disconnect clear the stream timers and subscriber slot. Only contacts visible at subscription time can generate hints during that connection; reconnect/sync after contact changes.

`createImCenter` owns the registry and composes it with the HTTP handler and the post-commit message callback. The initial contact snapshot and each continuing authorization/contact check run within one shared clock-guard read scope, not one scope per contact. Post-commit hints are queued with a trusted timer and coalesced per recipient so subscriber checks and socket writes do not delay the send response; timer failure only drops the hint. Backpressure, write failure, revocation, idle expiry and center shutdown destroy the stream; normal finish/close only cleans up. Timer rescheduling failure also destroys the stream. An optional trusted `eventsOptions` constructor argument exists for isolated tests/host configuration; it is never derived from request data. The caller owns the listener, host resource limits and network/TLS configuration. This feature has not been deployed or verified on LAN/Internet. Browser `EventSource` cannot set the Authorization header directly; a suitable authenticated SSE client/polyfill is necessary if using that API.
