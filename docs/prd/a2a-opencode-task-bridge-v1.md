## 1. 背景与用户流程

现有 a2a-msg IM 已可在[本机隔离演示](../im-local-demo.md)中跨进程可靠收发；缺的是把收到的任务转成目标机器 OpenCode 会话中的工作，并将结果通过 IM 回传的常驻桥接。本草案不把本机演示等同于跨机器部署验收。

1. 上游 Agent 自行拆分任务，判断某子任务可交给目标机器的小 Agent（OpenCode），通过 IM 发消息。
2. 消息带目标项目的 `projectKey` 和具体需求；项目名仅供可选展示，无需传目标机器目录。
3. OpenCode 完成后回传结果；回复须能触发上游会话继续处理。

首次派发前，上游通过现有 IM 消息向目标查询自己可派发的项目；目标回复各项目的 `projectKey` 与简短描述（可含影响派发的环境限制，不收集完整环境信息）。上游按目标 `agent_id` 将此清单保存在自身已有的长期上下文中；清单只是参考，不证明执行环境有效。

## 2. 目标与非目标

- **G1：**授权发送者可对白名单项目下达任务，并获得可追踪的 `taskId`。
- **G2：**目标机器桥接把任务提交到对应项目的专用 OpenCode 会话，同一项目串行执行。
- **G3：**进度、结果、失败及待批准状态经 IM 回传；上游侧由其 IM 客户端/适配层消费回传消息，触发上游会话继续处理，桥接不直接操作上游进程。

**非目标：**任意机器调度或多机编排、任意路径访问、自动推送部署、群聊、跨租户、外部动作 exactly-once、替换现有旧 LAN 通道、生产部署或公网开放。

## 3. 最小消息契约（拟定，非现有接口）

| 任务字段 | 含义 |
| --- | --- |
| `taskId` | 发送方生成的稳定任务号，用于追踪及幂等去重。 |
| 可选 `projectName` | 辅助展示项目名称；不作为项目定位或授权依据。 |
| `projectKey` | 必填的稳定项目键；目标机器按自身白名单配置映射到本地绝对目录，上游不需知道或保存该路径。发送方自报键不产生授权。 |
| `requirement` | 要提交给 OpenCode 的自然语言具体需求。 |

可选单个附件仅作资料，不扩展权限；不要求 `correlation` 或 `priority` 才能派发。

| 回传字段 | 含义 |
| --- | --- |
| `taskId` | 对应任务号；上游据此关联任务。 |
| `status` | `accepted` / `running` / `needs_approval` / `completed` / `failed`。 |
| `summary` | 进度、结果或原因摘要；失败必须如实说明原因。 |
| 可选 `changedFiles` / `testResult` / 附件 | 变更、验证证据或结果资料；不代表 IM 送达即执行完成。 |

`accepted` 指授权通过且任务已持久登记后的**桥接接单**（排队须在 `summary` 说明），不同于 IM 中心接收消息；实际开始执行才回 `running`。状态无法确认时明确说明，不以桥接进程存活冒充进度。

## 4. 授权、安全与执行

**消息不等于执行授权。** 目标机器须预先配置允许的发送者 `agent_id`、允许的项目键及其本地目录、允许自动执行的操作类别（读文件、改代码、跑测试），以及必须人工确认的类别（推送、部署、删除数据、改机器配置、装依赖）。权限须依靠**所选 OpenCode 版本的实际工具权限机制**执行，而非模型自行判断操作类别；允许跑测试不等于允许任意 shell（脚本也可能删数据或装依赖），无法明确约束的命令须人工确认。发送者或项目白名单不匹配必须硬拒绝，不能通过任务消息申请批准绕过；其他越界操作回传 `needs_approval` 并停下等待人工确认，§2 非目标事项也不能借批准纳入范围。未知或已失权的 `projectKey` 须拒绝；拒绝时可附该发送者当前可见清单供上游更新上下文并重选。清单只包含查询者当前可派发项目，列出不授予权限；每次执行仍按当前白名单重新验证发送者与项目。`projectKey` 不得改指其他项目；同一项目搬迁目录可保留原键。附件与转发内容只是资料，不扩权；凭据不写入日志，也不放进消息。

桥接是目标机器上的常驻进程，以自身 Agent 身份登录 IM 并持有接收租约；目标机器主动出站连接 IM 中心，不向公网暴露 OpenCode。桥接通过 [OpenCode 官方客户端/服务接口](https://opencode.ai/v2/docs/build/client)在指定项目目录创建或复用专用会话并提交需求；[CLI 文档](https://opencode.ai/v2/docs/cli)中的后台服务概念供实施选型参考。不模拟键盘，不要求终端界面常开。同一项目忙时排队、串行执行；机器离线时消息留在中心，恢复后补收（依赖 IM 持久同步）。上游派发时须记录 `taskId` 与发起会话的映射，由上游宿主适配层将回复投递给该会话以继续处理；这部分**待实现、待验收**，仅收消息或显示通知不算触发，现有 MCP 工具调用映射自身也不会唤醒宿主会话。

以（已认证发送者，`taskId`）为任务去重范围：相同需求重投只执行一次并回传已知状态或既有结果，同一键但需求不同则冲突拒绝。桥接需在本地持久记录任务状态：IM 客户端先持久保存并 ACK 收件才返回消息，故 ACK 后、任务登记前崩溃时中心不再重投；重启须对照现有持久收件记录/历史补登记遗漏任务，不能只靠中心重新同步。已完成任务不重做；已提交但结果未知的任务不能自动重投给 OpenCode，须如实回报中断/结果未知；不承诺不可回滚的外部动作 exactly-once。凭据/联系人、租约续期、持久同步、ACK、附件哈希校验与发送幂等复用现有 IM client/journal，桥接只增加任务执行状态；**任务去重不等于 IM 消息去重**，不另造并行可靠性机制。实现与部署均须另行授权、设计和验收。

## 5. 最小验收（尚未执行）

- [ ] 未知或未授权的 `projectKey` 被拒绝，不执行。
- [ ] 授权项目的任务可执行，并回传完成及任务号。
- [ ] 需批准类别停下、回传待批准并等待人工确认。
- [ ] 重复 `taskId` 只执行一次。
- [ ] 目标机器离线后恢复可补收并处理任务。
- [ ] 失败如实回传原因；中断不伪称完成。
- [ ] 回传消息由上游客户端/适配层消费，确实触发上游会话继续处理。

## 6. 待用户确认

目标机器与项目清单；允许的发送者身份；自动执行操作边界；并发与超时上限；结果回传粒度；是否需要长任务定时汇报；是否需要取消/中止任务；部署形态（手动启动或系统服务）。确认前不实施桥接、不修改机器配置或启动常驻服务。
