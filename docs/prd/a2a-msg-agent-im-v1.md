## 0. 写前门槛评估

需求边界已确认：独立 Agent 互为联系人；v1 单中心单管理域、双方可读**新**私聊、旧数据不扩权、一个 Agent 仅一个有效接收实例；LAN 私有中心和互联网 TLS 可达中心均为 v1 验收项。新增写前门槛：产品不能以 OpenCode、研发工单或内部人名为必备前提；公开仓库治理须作为独立工作流，不等于授权修改仓库设置。身份凭据、接收租约、同步与 ACK 需要新增实现，不能拿当前 LAN 版或 SSE 源码冒充完成。许可证、留存参数、资源预算等尚未决定，均列于末尾待确认，不妨碍本草案写作但**阻止据此直接上线**。参考仓库事实：[README](../../README.md)、[中文入口](../../README.zh-CN.md)、[工具参考](../tools.md)、[管理员指南](../admin.md)、[OpenCode SSE 源码说明](../../integrations/opencode/README.md)；旧 PRD 仅作历史背景，不能用其中的过期状态当当前事实。

## 1. 背景与产品定位

**a2a-msg 是 AI Agent 领域的 IM。** 独立 Agent（不是只能由主 Agent 调度的 subagent）可互为联系人，建立私聊会话、交换消息/附件，离线后同步消息。跨空间指不同机器、网络、框架及进程；跨时间指稳定 `agent_id` 不因会话、实例、重启或离线而改变。workspace 可预留地址命名空间，但用户自报 workspace 不产生跨租户授权。a2a 仅指 agent-to-agent，**不承诺兼容官方 A2A 协议**；通信中心不替换 Agent 运行框架，送达不代表同意或授权执行消息内容。

## 2. 目标、非目标与场景

**目标 G1：**管理员登记并允许互相联系的两个独立 Agent，能在新私聊会话中互读自身参与的消息及附件，旧数据不因此扩权。

**目标 G2：**同一稳定身份可跨实例生命周期接续；一个 `agent_id` 同时仅有一个有效接收消费者，发送重试、离线同步和确认可跨崩溃恢复。

**目标 G3：**同一套客户端出站 HTTP/SSE 契约在私有 LAN 中心与互联网 TLS 可达中心分别验收，不依赖 P2P、NAT 穿透或跨中心联邦。

典型场景：①调研 Agent 把资料传给写作 Agent，写作 Agent 自行选择采用并回复；②数据分析 Agent 给报告 Agent 传单个图表附件，不要求共用框架；③收件 Agent 离线、中心重启后另一个实例接管并补收、确认。研发/测试交接可作为第四个可选实例，QA/FIX 并非核心角色或强制消息格式。**非目标：**群聊、音视频、全球联系人发现、跨租户/跨组织审批、联邦/多中心/HA/broker、大文件/多附件/断点续传、完整官方 A2A adapter、自动值守上线或外部动作 exactly-once。通信状态不包含 `executed`。

## 3. 产品契约与需求

### 3.1 身份、联系人与网络（R-ID、R-ACL、R-NET）

- **R-ID**：管理员引导注册不可复用的稳定 `agent_id`，`display_name` 可修改但不能用作授权标识；`instance_id`、框架 session 和租约代际不是身份。各 Agent 有随机生成、彼此独立、可撤销/轮换的凭据；只在安全存储中持有，服务端仅保存不可逆验证材料（例如凭据 hash），日志不得输出明文或完整凭据。sender 必须由服务端认证结果确定；客户端自报 `from` 不生效。失败或撤销的凭据**绝不回退**到来源 IP 身份。
- **R-ACL**：管理员在单管理域登记联系人 allow-list，明确双方联系策略；未批准的 Agent 不得搜索、发往、读取或引用其他 Agent 的会话、消息、附件，猜测 ID 也不可越权。私聊 `conversation_id` 固定恰好两个成员；新协议创建的会话仅这两方可分页读取新消息、附件与自己的发送记录。发送方查看自己已发历史不改变接收方 `delivered` / `read`。管理员对关系或身份撤销时，后续请求、长期连接及附件传输须重验权限；已到本地的文件不能远程收回。撤销后历史访问策略发布前须明确定义，不得泄露给第三方。
- **R-NET**：两种必验收模式：私有 LAN 内单中心与不同网络客户端连互联网 TLS 可达单中心。客户端主动出站 HTTPS（含 SSE）而非直连其他 Agent；互联网及任何非 loopback 默认强制 TLS 和有效证书，凭据不能走明文。即便 LAN 要放宽非 loopback TLS，也须独立安全决策，**本草案不默认开放 HTTP 凭据传输**。IP 可以限制来源网络，不能充当 Agent 身份；TLS 终止和代理后身份依靠凭据验证，非代理头。公网资源和真实凭据申请须另行授权，不以本机模拟冒充互联网验收。

### 3.2 消息、附件和状态（R-MSG、R-STATE）

- **R-MSG**：版本化新协议支持 `conversation_id`、服务端 `message_id`、客户端 `client_message_id`、认证 sender、目标 `agent_id`、可空标题、正文、至多一份附件（沿用原文件 ≤10 MiB 和 SHA-256）。`title: null` 合法，界面显示「无标题」；空正文+有效附件合法，正文/附件皆空拒绝。`in_reply_to` 可选且只指本会话中可见的消息；可选 `correlation` 只关联一次请求/事务，不另造编排子系统。附件仅授权双方可取，不能让中心远程抓取任意 URL。地址可以预留 domain/workspace 命名空间用于未来扩展，但不可单凭用户自报值跨域授权，也不把永久中心 URL 编进 `agent_id`。
- **R-STATE**：`accepted` = 中心持久事务原子提交消息、附件及发送幂等记录（失败不留下可见半条）；`delivered` = **有效接收实例**完成安全持久接收（附件 SHA-256 校验并保存）后显式、幂等 ACK；`read` = 接收方另行显式确认阅读。只 GET、SSE 到达、网络断开、下载中或 hash 失败都不能提前 ACK；发件方读取自己的记录不更改对方状态。`executed` 不属于 IM 状态；旧数据的有效末页自动标读语义保留在旧入口，不误认新协议 ACK。消费者至少一次重试，按 `message_id` 去重，不承诺上层外部动作 exactly-once。

### 3.3 发送幂等、接收租约及离线同步（R-SEND、R-LEASE、R-SYNC）

- **R-SEND**：SQLite 持久记录以 `(authenticated sender agent_id, client_message_id)` 为作用域；规范化完整 payload 指纹至少包含接收 Agent、会话、文本/标题、附件 hash、`in_reply_to` / `correlation`（含版本与内容关键字段）。同 key 同 payload 返回同一个 `message_id`，同 key 不同 payload 冲突。响应丢失/超时时，先按同一身份与 key 查询结果，再用**原 key、原 payload**重试；未知结果不另起 key 盲发。幂等记录和消息原子提交；保留期与消息 TTL、最迟安全重试窗口须发布前联动决定，过期 key 不可静默当作安全重试。
- **R-LEASE**：同一个 `agent_id` 同时最多一个有效**接收消费实例**，服务端基于自身时间维护带 expiry 的租约与单调 fence generation；接收、ACK、推进游标时校验有效租约/fence。第二实例在占用期默认拒绝，不静默抢占；到期或管理员明确接管后递增 fence，旧实例不得 ACK/推进游标。中心重启采用持久租约并重新验证有效期和 generation，不能出现双有效实例；断开 SSE 不立即改变长期身份、可读历史或租约状态。发送、授权历史查看与控制界面可以并存，但**没有合法接收租约的 MCP/展示客户端不能推进 delivered 游标**。TTL、心跳及管理员接管细则由实施设计定量确认。
- **R-SYNC**：按认证 Agent 持久保存接收游标和 ACK（不可跨主体泄露计数、位置或存在性），并提供分页补收。SSE 仅低延迟变更提示，内存 ring 不是 durable replay，也不能推进 ACK；离线、断线、中心重启后总以 SQLite 持久同步补齐。ACK 与服务端游标推进同事务，重复 ACK 幂等；客户端须有最小持久 journal / 收件记录或等价可证明机制：在附件校验安全落盘后、ACK 前崩溃，重启仍能按 `message_id` 去重并补 ACK，不能跳过未确认项。仅列历史私聊分页与接收流游标分离；不能按 unread 筛选做同步。重复页、过期游标须明确 reset 并从仍保留的最早位置恢复，绝不静默跳过；留存到期/缺口必须可检测并告知管理员。

### 3.4 接口与数据语义（目标契约，非现有路径）

新协议需命名空间和版本标识，与旧 IP 入口隔离；具体 URI/HTTP 错误码由 WP1 契约定稿，下表为必须具备的动作，不是声称 API 已存在。

| 动作 | 请求 / 响应与权限要点 |
| --- | --- |
| 管理员注册、撤销、允许联系 | 生成 `agent_id` 与独立凭据，只返回一次密钥材料；关系规则由管理员管理，审计不记密钥。 |
| 新建/列出私聊会话 | 两个固定成员、联系规则通过；仅参与方分页查询历史；非参与方不泄露存在性。 |
| 发送消息、按 client key 查状态 | 认证 sender，验证对方及本会话；返回同一 `message_id`、`accepted`；失败重试按 R-SEND。 |
| 接收租约、续期、显式接管 | 服务端时间与 generation；冲突拒绝或管理员接管并 fence；接收权不同于历史查看权。 |
| 持久增量同步、附件领取与显式 ACK | 按主体/租约分页，授权下载并校验附件，客户端持久收件后 ACK；与 cursor 原子推进，过期显式 reset。 |
| 显式 read、SSE 通知 | `read` 由接收方确认；SSE 只提示重新同步，无保序持久推送或消费确认保证。 |

持久数据至少包括不可复用 Agent ID、凭据验证/撤销元数据、联系人关系、私聊固定成员、消息与附件 hash、幂等 key+指纹、接收状态/游标、租约代际和必要审计元数据。所有查询先按认证主体约束，再查会话或消息；不因引用、附件 ID 或 workspace 自报绕过授权。留存、备份/恢复和存储满的行为须与同步缺口检测一致。

### 3.5 平台无关模块与兼容边界（R-MOD）

**R-MOD：**按职责建立可测试的逻辑边界，而非强迫立即拆 monorepo、微服务或多个 npm 包。

| 模块边界 | 职责 / 依赖方向 |
| --- | --- |
| core 通信契约 | Agent 身份、联系人、私聊、消息状态、幂等、ACK / 恢复与附件 ACL；不能 import OpenCode、模型 SDK、研发角色/工单模板。 |
| 存储与传输 infrastructure | SQLite、HTTP、SSE 实现 core 契约；部署模式的 TLS / 网络配置与业务模型分离。SSE 不取代持久同步。 |
| 通用 client | 凭据/session、同步游标、单附件安全保存、journal、重试及标准错误；不依赖宿主 TUI/question/Skill。`instance_id` 是运行实例而非 Agent 身份。 |
| MCP adapter | 平台中立地映射通用 client/服务契约到 MCP；现有十工具与旧阅读路径保留兼容，不使新接收/ACK 强制人工交互。 |

## 4. 失败、兼容与迁移

| 情况 | 预期处理 / 必验断言 |
| --- | --- |
| 无标题、仅附件；双空、超 10 MiB、hash 错 | 前两者分别合法并显示「无标题」/正文为空；双空与超限拒绝；hash 错不交付、不标 delivered、不推进游标。 |
| 错误/撤销凭据、联系人撤销、访问第三方 ID | 不退回 IP 身份；发送、读取、引用、附件和长连接续权均拒绝；传输途中撤销时停止后续交付/ACK 并重验，已安全落盘内容按既定权限策略处理。 |
| 相同 key 重发、不同 payload、重复 ACK | 相同完整 payload 同 ID，不同 payload 明确冲突；ACK 重复幂等且仅当前有效 fence 可做。 |
| 第二接收实例、租约过期/接管、中心重启 | 占用期默认拒第二实例；新 fence 生效旧实例不得 ACK/推进；持久租约重验不产生双实例。 |
| 部分附件保存失败、客户端崩溃、丢失发送响应 | 不提前 delivered；journal 恢复/重复消息去重；查询 key 后同 key 重试只一条。 |
| SSE 丢帧、旧/过期 cursor、离线重启 | 拉取持久补收；游标过期显式 reset/报告留存缺口，不默默跳到最新，也不依赖 unread 筛选。 |
| 限流、存储满、事务/进程失败 | 标准化错误和退避（尊重可用的 Retry-After）；不得提交半条消息或错误 ACK；重试可查询最终结果。 |

**迁移要求（R-MIG）：**使用追加式 schema version 和预览校验；先做可恢复备份。管理员人工审核每个旧 member→新 `agent_id` 绑定，不能凭同名自动认领；旧消息标识为 `legacy_ip` 来源，不追认为强身份。新私聊双方可读**仅适用新会话/新协议消息**；旧消息 ID、`read_at`、附件及原收件权限保留，旧读到有效末页即标读语义继续保留；历史 `reply_to` 不得未经迁移直接复活。旧 API 与新凭据 API 分离入口/namespace，身份失败不跨入口 fallback。旧接口截止策略待确认。升级顺序：schema/备份与预览 → 管理员凭据/联系人白名单 → 限定 Agent 灰度 → 双模式验收 → 决定扩大范围。回滚可停新写并保留已 accepted 的新消息、幂等和 ACK 记录，不能用旧 DB 快照覆盖升级后新增消息。品牌本轮仅文档；包名、bin、MCP 别名、安装配置或仓库远端 rename 另获批准并实测。

## 6. 待确认（维护者/实施设计，不擅自代答）

1. 许可证选择：当前无 LICENSE，公开仓库不等于开源授权；是否、何时添加由维护者决定。
2. 消息/附件 TTL、幂等 key 去重保留期、安全重试窗口、过期游标恢复及备份/隐私策略须联合定量，不能凭默认无限保存。
