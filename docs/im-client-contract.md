# Isolated IM client (v1)

`createImClient({serverUrl,agentId,getCredential,journal,attachmentDirectory,transport?})` is an explicitly invoked HTTPS-only adapter. `journal` is a **trusted factory** invoked with `{centerId: normalizedHTTPSOrigin,agentId}`; the installer MUST construct `createImJournal({db,...scope})` from those values, not hand over an already-created uninspectable journal. The installer owns persistent SQLite (`synchronous=FULL`), protected absolute attachment directory and its ACL, and trusted async credential provider. An optional `transport` is a privileged internal test/CA integration seam, never sourced from model/request input; do not use it to bypass certificate validation. The default Node HTTPS transport verifies certificates and hostname and never follows redirects. No credential is put in URL/body/journal. Each top-level operation snapshots its credential once, authenticates `/me`, then reuses that snapshot for every business request. The server may still reject a revoked credential. The host must bind `getCredential` to its current authorized session; this client cannot bind an external host session.

`send(rawRequest)` stages locally before the first POST, and validates sender, recipient, conversation, key, content and attachment metadata against both authenticated send result and independent GET `/messages/:id` before marking accepted. Existing pending records are queried by `/sends/:key`, never POSTed automatically. `recoverSend(key)` explicitly checks key then performs at most one POST of the stored request after 404. An uncertain network result remains pending, never gets a new key. Retry after the server's idempotency window may fail with `IDEMPOTENCY_WINDOW_EXPIRED`; manual reconciliation is then required. A staged accepted record is also revalidated remotely. No automatic recovery loop exists.

`acquire({instanceId,requestId})`, `renewLease()`, `release()` are explicit; historical acquire performs a server renew before caching. A process restart requires fresh renew. `receiveOnce({limit=20})` renews the cached fence, fetches one bounded sync page, checks stream epoch and sequence, validates messages and downloads authorized attachment bytes. File names derive from the center/agent hash and message/attachment IDs, not remote names. Files are exclusively created and fsynced, existing files independently checked for SHA-256 and size. All messages are journaled after file verification and before ACK. `ackPending({limit=20})` explicitly reconciles a pending page and local receipts against the authenticated server and live fence before retrying ACK; no silent stream reset or ACK on revoked identity. ACK response includes only `{ackedThrough}`; trusted sync epoch/watermark, local cursor and submitted sequences bind the local `markAcked` call. The ACK watermark cannot exceed the locally provable continuous ACK range, including older ACKed rows bridged by a newly filled hole. `receiveOnce` only returns `status:'delivered'` after authenticated ACK and durable local mark. Errors are safe IM codes, not remote text/paths. A failed ACK leaves pending journal records; caller uses `ackPending` explicitly. `close()` aborts current default transport requests and rejects future work; injected transports must independently honor their own cancellation contract.

**Boundaries:** no background worker, SSE, model invocation, automatic reply, automatic polling, TLS-disable switch, production mounting or deployment. Default transport has both a 30-second socket idle timeout and an independent 30-second total request deadline; incomplete/aborted responses fail closed. Responses are bounded to 16 MiB JSON and 10 MiB binary. Remote business text and attachments are untrusted data. Attachment directory must already exist, resolve to itself (no symlink/junction, including parents), and be provisioned for exactly this scope by the installer. Final files use `lstat`, realpath, and open-handle identity checks, not POSIX `O_NOFOLLOW` as a Windows guarantee. A strictly named same-scope hard-link publication temp can be removed after identity/size/hash verification; unrelated hard links fail closed. A local attacker with directory write permission can still race concurrent replacement: enforce installer-owned directory ACL isolation. A fresh factory must be used for each agent/center. No automatic journal cursor reset: `CURSOR_RESET_REQUIRED` requires an external explicit reconciliation policy. Local disk damage or changed files fail closed. Tests include a real isolated TLS handler with explicit trust of a localhost-only test CA through the privileged transport seam; this does not establish internet deployment readiness.
