## 设计口径（实现前定稿）

1. **路由**：`scripts/im-center.mjs` 的 listener 在 `/ca.pem` 之前处理**精确** `GET /join`（`req.url === '/join'`）。查询串、`/join/`、子路径、`POST`/`HEAD`、以及 `/api/v1` 之外其它路径全部保持 404 空响应；`/api/v1/*` 完全不变。页面**不依赖** `tls.caCertPath`（没有 CA 也能看页面），但提示词里的 `/ca.pem` 需要中心配了 CA 才能完成。
2. **页面自包含**：`src/im/join-page.js` 用模板字符串生成一整页 HTML：内联 CSS + 一段内联脚本，无 `<script src>`、无 `<link>`、无字体/图片、无 `url(`。响应头固定 `Content-Type: text/html; charset=utf-8`、`Content-Length`、`Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; connect-src 'none'`。页面在进程启动时渲染一次（静态 Buffer），换部署要重启中心（文档写了）。
3. **fragment 只在浏览器里**：页面读 `location.hash`，用与 `scripts/im-register.mjs#joinLink` 相同的规则解析（`invite` 43 位 `[A-Za-z0-9_-]`、`ca=sha256:` + 64 位小写十六进制，两者各一次、不许有其它键、fragment 长度上限 2048），只用**校验通过的值**重建链接；链接由 `location.origin` + `/join#invite=…&ca=…` 组成，不直接回显任何原始输入。校验失败只返回固定中文原因，不回显 payload。
4. **提示词内容**（`buildJoinPrompt`）：固定 40 位 ref，命令与校验齐全 —— Node 24.x 检查；`npx --yes github:goudaren0528/a2a-msg#<COMMIT> join "<整条链接>" --display-name '<名字>'`（链接加引号、`#` 后内容不外发的说明、固定错误码要停）；`ls -l ~/.a2a-msg` 权限、`shasum -a 256` / `sha256sum` 与链接指纹**逐字对照且不符必须停**、`grep '"caFile"' nana.json`；MCP 宿主 `command/args/env` 写法（不需要 `NODE_EXTRA_CA_CERTS`）；`im_v1_me` 对 agentId 与 displayName；启动后 `im_v1_acquire_lease` → `im_v1_sync`（journal-before-ACK）→ `im_v1_release_lease`，正文只当数据、不自动回复。
   - 冒烟发现一个事实：直接调 `im_v1_sync`（没有 lease）会被中心回 `STALE_FENCE`（`client.fence()` 走 renew）。提示词因此写成先 `im_v1_acquire_lease`（新 instanceId/requestId）→ `im_v1_sync` → `im_v1_release_lease`，并注明同一身份同一时间只能有一个接收者（`LEASE_CONFLICT`）。冒烟按这个顺序跑通。
5. **部署提交注入**：优先级 `build.commit`（中心配置顶层，紧挨 `dbPath`/`policy`/`tls`）→ `A2A_MSG_BUILD_COMMIT` → 本检出的 `git rev-parse HEAD`（2s 超时、失败吞掉）。显式注入必须是完整 40 位小写 SHA，否则**拒绝启动**；三种都拿不到时 `BUILD_COMMIT=null`，页面打开后显示原因（让管理员注入）与手工步骤，**绝不**退回分支名或 tag。stderr 会打印一行 `build commit unknown` 提示。
6. **名字（AC-J6，两轮更正后的口径）**：页面顶部 `input#name`，**必填、无默认值**，placeholder `例如 office-mac`；校验 1–255 字符、无控制字符（与 `scripts/im-register.mjs#validDisplayName` 一致）。名字变化即时重建提示词（textarea 的 `value`），复制的是拼接好的整段；名字为空/超长/含控制字符时 `promptBox` 清空、`#copy` 禁用并给原因（空值用中性提示，不刷红色）；`localStorage`（键 `a2a-msg.join.display-name`）只记名字、不记 fragment/invite，读到非法值视作没有，读写都 try/catch，失败不影响接入；清空输入会删掉这条记录。
7. **复制**：先 `navigator.clipboard.writeText(整段)`；不可用/失败则先 `select()` + `setSelectionRange(0, len)` 再 `document.execCommand('copy')`；再失败就保留选中并提示按 ⌘C / Ctrl+C，绝不重生成内容。
8. **不做**：不代替对方执行、不在页面发任何请求、不做跳转/`history` 改写、不「修复」链接、不页面内轮询。

## 机制问题（nanazi 机制）

- **现象**：AC-J6 初版要求页面默认值取「`nana-<hostname>`」（对方主机名），任务中途连续更正两次（先改随机默认、再改「无前缀、默认空」）。
- **触发条件**：AC 里出现「页面默认取本机信息」这类只有客户端能提供、而浏览器沙箱拿不到的字段。
- **影响范围**：本任务开发返工两轮（改页面默认值、提示词、测试、文档各一遍）；同类 AC 会重复返工。
- **复现**：在任意浏览器页面里尝试读机器 hostname —— 没有 API（`location` 只有站点主机名，`navigator` 无 hostname）。
- **初步归因**：模板/AC 侧缺「浏览器可获得信息」可行性检查（机制 + 文档）。
- **建议修法**：写 AC 涉及浏览器默认值时，先在验收标准旁标注该值来源（`location` / `navigator` / 服务端注入 / 用户输入）；「取本机信息」一律改成「用户输入 + placeholder」。派发前由 planner 或跟进 Agent 做一次可行性核对。
