## 设计口径（实现前定稿）

- **bin 只做分发，不复制业务逻辑**：`bin/a2a-msg.mjs` 顶部只导入 Node 内建模块，`mcp` 子命令转发到 `scripts/im-mcp.mjs`，`register` 转发到 `scripts/im-register.mjs`（`process.execPath` + `stdio: 'inherit'`，信号与退出码透传）。这样旧入口仍是唯一实现，npx 只是多一层入口。
- **Node 版本**：执行任何子命令前检查 `process.versions.node`；与 `engines: >=24 <25` 一致，主版本不是 24 时 stderr 输出固定码 `NODE_VERSION_UNSUPPORTED` 并退出 1。`--help` 也在检查之后（Node 不对时先报版本）。
- **帮助**：`a2a-msg --help`、`a2a-msg mcp --help`、`a2a-msg register --help` 都只打印用法并退出 0；帮助路径不导入 `scripts/`，因此解包后的 tarball 在没有任何 `node_modules` 时也能跑 `mcp --help`。
- **打包**：`package.json` 增加 `bin: { "a2a-msg": "bin/a2a-msg.mjs" }`，`files` 增加 `bin/`、`scripts/`；`private: true` 不变（不发布 npm），AC-9 走 `npx github:<repo>#<commit>` 或本地 tarball。`docs/` 整目录在 `files` 里，会连带收进只在工作区存在的本地证据；因此增加 `!docs/delivery/*/evidence/`、`!docs/delivery/*/shots/` 两条负向规则。
- **固定 ref**：文档只给完整 commit SHA 的形式，不给分支名；提交号由使用方从已批准版本解析。
- **不改旧入口**：`node src/mcp.js`（LAN bridge）与 `node scripts/im-mcp.mjs --config`（IM v1 stdio）保持原样。

## 性能 / 安全自查（只看变更路径）

- **性能**：`mcp`/`register` 每次调用只多起一个 Node 子进程（`spawn(process.execPath, ...)`），无定时器、无 watcher、无后台任务；`--help` 路径不加载任何依赖，冷启动只解析内建模块。tarball 约 910 KB（`docs/` 占大头，证据/日志已排除），npx 首次下载后走缓存。
- **安全**：版本检查在参数解析之前；错误只输出固定码（版本错误附带运行版本号）；不打印凭据；`register` 仍由原脚本写 `0700`/`0600`；`mcp` 的 stdio、信号和退出码原样透传，不新增网络路径；打包排除本地证据目录，避免测试日志/本机路径随包分发。
- **残余风险**：npx 首次运行需要访问 npm registry；离线目标机应使用本地 tarball。`npx` 会在 npm 缓存里保留已下载的包，这是 npx 语义，不在本包消除。

### 机制问题（nanazi）

1. **派发说明再次引用本仓库不存在的测试入口**（P1/P3/P5 已报，本次原文复现）：任务说明写「测试公共入口 `tests/_isolation.py` 已默认带上 `NANAZI_NO_SEND=1`」，但 a2a-msg 仓库没有该文件，全仓也没有 `NANAZI_NO_SEND` 的使用。现象：开发只能自行在每个测试命令前加环境变量。触发条件：跨项目派发复用 nanazi 仓的测试约定。影响范围：所有 a2a-msg 派发。复现：`ls tests/_isolation.py`、`rg NANAZI_NO_SEND` 均无结果。初步归因：模板/文档（跨仓约定混用）。建议修法：任务模板按项目注入测试入口，或写明「本项目无此入口，仅设置环境变量」。
2. **AC-9 的 tarball 命令写法不可直接执行**：验收写 `npx <tarball 或 git ref> mcp --help`，但 `npx <本地 .tgz>` 会把 tarball 当可执行文件，报 `sh: ... Permission denied`（退出 126）；正确形式是 `npx --yes --package=<tarball> a2a-msg mcp --help`。现象：按验收原文执行 tarball 分支会误判失败。触发条件：用本地 tarball 而非 Git ref 验收。影响范围：P4 及后续要求 npx/tarball 验收的任务。复现：`npx --yes /abs/team-mailbox-0.1.0.tgz mcp --help`。初步归因：计划/验收文案未区分 npm 的「命令」与「package spec」两种位置参数。建议修法：验收写全两种形式（Git ref 直连、tarball 用 `--package`），或在文档里链接本包的 install-npx 说明。
