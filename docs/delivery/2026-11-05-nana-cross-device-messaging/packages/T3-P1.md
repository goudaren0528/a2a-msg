### 机制问题（nanazi）

1. **任务说明的 Node 版本与仓库要求冲突（本人已确认按 24，仍建议改模板）**。现象：`dev-task.md` 写「装 Node.js 22」，仓库 `package.json` 的 `engines` 是 `>=24 <25`、中心依赖内置 `node:sqlite`（Node 22 需实验开关，`npm ci` 会按 engines 报错）。本次按仓库要求装 Node 24.22.2，本人 2026-11-07 已确认「装 24 就对，公司机按 24 写说明」。触发条件：派发说明按经验写运行环境、未读仓库 `engines`。影响：照说明装会起不来，开发要自己判断该不该偏离说明。复现：`git show origin/master:package.json | head -6`。初步归因：模板/文档（派发说明未从仓库取）。建议：模板里运行环境写成「按仓库 `package.json` engines」，或派发时抓一次 `engines`。
2. **任务标题/目标行把子项复选框重复拼了四次**。现象：`dev-task.md` 的「目标」与 run 记录 `title` 都是 `两台真实设备接入- [ ] T3 两台真实设备接入- [ ] T3 …`（重复 4 遍），run 记录 `title` 字段被污染。触发条件：计划任务行的子项文本被重复拼进标题。影响：run 记录、通知标题、索引可读性；按标题检索/去重会失准。复现：`head -3 runs/2026-11-07-…-T3-team-mailbox-347c.md` 的 `title:`。初步归因：脚本（标题生成）。建议：标题只取任务行一级文本，子项（`- [ ]`）不参与拼接，并加一条生成后校验（同一片段重复即报错）。
3. **派发说明的测试入口在本仓库不存在（与 T2 同一条）**。现象：说明写「跑测试必须带 `NANAZI_NO_SEND=1`（测试公共入口 `tests/_isolation.py` 已默认带上）」，a2a-msg 仓没有 `tests/_isolation.py`，全仓无 `NANAZI_NO_SEND` 引用。影响：开发要自己判断开关是否适用（本次仍按说明带上了环境变量，但它对 Node 测试无作用）。复现：`ls tests/_isolation.py`、`rg NANAZI_NO_SEND` 均无结果。初步归因：模板/文档（跨仓约定混用）。建议：模板按项目区分测试入口，或在说明里注明「本项目无此入口」。
