## 设计口径（实现前定稿）

- **权威关系**：`im_contacts.allowed=1` 即「accepted」；ACL（`requirePeer`）不变，所以发送/会话/历史/附件/同步的服务端强制沿用同一条路径。
- **状态机**：`im_contact_requests`（P1 已建）保存每次方向性申请，`status ∈ pending/accepted/rejected/revoked`、`version` 每次变更 +1。
  - `request(A→B)`：未好友时建/复用 pending；已是好友时幂等返回 accepted（缺 accepted 行则物化一条，兼容管理员 `set-contact`）。
  - `accept`：只有 target 可操作、只能 `pending → accepted`；同对的反向 pending 一并接受（双向同意捷径），并 upsert `im_contacts.allowed=1`。
  - `reject`：只有 target 可操作、只能 `pending → rejected`；不改 `im_contacts`。
  - `revoke`：requester 取消自己的 pending，或任一方解除 accepted；`accepted → revoked` 时 upsert `im_contacts.allowed=0`，同对其它 accepted 行也置 revoked。撤销后 ACL 立即失效 → 旧历史不可见（q08 B）。
  - 非法迁移返回 `CONTACT_REQUEST_CONFLICT`；不存在/非本人返回 `RESOURCE_NOT_FOUND`（不泄露）。
- **policy**：`contacts.requests = 'enabled' | 'legacy'`，默认 `legacy`（旧行为：只认 `allowed=1`、忽略请求表、无好友路由）；`enabled` 才开放申请/接受/拒绝/撤销；两种模式都继续接受管理员 `set-contact`。
- **接口**：
  - `POST /api/v1/contact-requests {peerAgentId}` → 201 DTO
  - `GET /api/v1/contact-requests?direction&after&limit` → `{items,nextCursor}`，`direction ∈ incoming/outgoing/all`
  - `POST /api/v1/contact-requests/:requestId/accept|reject|revoke` `{}` → 200 DTO
  - MCP：`im_v1_contact_request`、`im_v1_contact_requests`、`im_v1_contact_respond`、`im_v1_contact_revoke`（16 → 20 个工具）
  - DTO：`{requestId,requesterAgentId,targetAgentId,peerAgentId,peerDisplayName,direction,status,version,createdAt,updatedAt}`
- **审计**：`contact_request_sent` / `contact_request_accepted` / `contact_request_rejected` / `contact_revoked`，只写 ID/status/version。
