## 设计口径（实现前定稿）

1. **注册成功后只留一个主复制区**：主机选择（Claude Code 默认 / Codex / 通用 JSON）只渲染当前宿主的唯一配置，下面只有一个主按钮「复制配置」。不再同时展示 agentId、Claude 命令、通用 JSON 三块可复制文本。
2. **三种配置内容**：
   - Claude Code：`claude mcp add --transport http a2a-msg <origin>/mcp --header "Authorization: Bearer <credential>"`（单行）。
   - Codex：`[mcp_servers.a2a-msg]` + `url = "<origin>/mcp"` + `http_headers = { Authorization = "Bearer <credential>" }`（三行，追加到 `~/.codex/config.toml`；已用本机 `codex mcp list --json` 核实该键被识别）。
   - 通用 JSON：与 P9 相同的 `mcpServers` 结构，压缩为单行，便于横向滚动。
3. **agentId**：从 textarea 改为单行小字 `<p>agentId <code id="agent-id">…</code></p>`，不占大文本框，不额外提供复制按钮（令牌已在配置里）。
4. **步骤条**：顶部 4 步「1 填名字 → 2 直接注册 → 3 复制配置 → 4 粘进宿主」；状态按空名字 / 名字合法 / 注册成功 / 复制成功推进，`aria-current="step"` 标当前步。切换宿主会重置复制状态并退回第 3 步（当前宿主的配置还没复制）。
5. **折叠**：「提示词（本地 CLI）」放进 `<details id="other-ways">`，默认收起；手工步骤也放进默认收起的 `<details id="manual">`，只有链接无效 / 缺部署提交时自动展开。Windows 文案明确优先直接注册，不需要 Node/npx；npx 提示词仅在 macOS/Linux 且宿主不支持 HTTP MCP 时作为回退。
6. **高度**：主配置 textarea `rows="3"`、`wrap="off"`、固定 3 行高度并横向滚动；提示词 textarea 只在展开后的回退区出现。窄屏保留 16px 输入字号与 44px 按钮高度。
7. **原有功能不删**：直接注册、CLI 提示词生成与复制、CA 指纹校验说明、手工步骤、固定错误码、令牌只存内存/DOM、不写 localStorage、不进 URL、刷新隐藏令牌，全部保留。

### 机制问题（nanazi 机制）

- **现象**：本工作区创建时 HEAD 是 `6bfc971`（P9 合入前），任务说明写的基线是 `origin/feat/a2a-no-install` `2e27dca0`；开工时若直接改页面会基于缺少 P9 直接注册的旧树。
- **触发条件**：需求分支在前一个任务合并后没有更新，工作区分支复用旧 HEAD。
- **影响范围**：本次开发需先 `git fetch` + `git merge --ff-only origin/feat/a2a-no-install` 才到基线；同类任务会重复；运行记录 `base_head` 仍写 `6bfc9718`，与任务行基线不一致。
- **复现**：`git rev-parse HEAD` = `6bfc9718…`、`git cat-file -t 2e27dca0` 在本工作区初始不存在；`dev-task.md` / 任务行写 `2e27dca0`。
- **初步归因**：工作区创建/基线解析机制（派发时没有校验或更新 feat 分支）。
- **建议修法**：派发前校验工作区 HEAD 等于任务行基线，不一致先 fetch/ff 或拒绝派发；运行记录 `base_head` 与任务行基线取同一来源。
