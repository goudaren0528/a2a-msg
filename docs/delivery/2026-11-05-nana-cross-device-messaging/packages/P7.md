- 对应 AC：AC-F1（兑换后自动双向 accepted）、AC-F2（join 后三件套齐全，MCP 无需 `NODE_EXTRA_CA_CERTS`）、AC-F3（任一 Agent 发邀请、只与邀请人成为好友、日限/撤销/过期的固定错误码）、AC-F4（`agentsCanInvite` 开关；旧路径不破坏）、AC-F5（v4→v5 可重复、拒绝 v1/v2；全量回归新增失败 0；文档与 CHANGELOG）

## 设计口径（实现前定稿）

1. **schema v5（additive）**：`im_enrollment_invites` 加一列 `inviter_agent_id TEXT REFERENCES im_agents(agent_id)`（默认 NULL）+ 索引 `im_enrollment_invites_inviter(inviter_agent_id,created_at)`。`inviter_agent_id IS NULL` 表示管理员邀请（旧路径不变）；非空表示某个 Agent 自己发的邀请。`IM_SCHEMA_VERSION=5`，`SUPPORTED_IM_SCHEMA_VERSIONS=[1,2,3,4,5]`。
   - `migrateImSchemaV5(db)`：空库直接建 v5；v4 → 加列 + 索引 + 换 marker；重复调用返回 `true`；v1/v2/v3 一律 `IM_SCHEMA_MISMATCH`。新鲜路径与迁移路径的 `sqlite_master` 文本逐字节相同（有测试钉住）。
   - 新 CLI `scripts/im-migrate-v5.mjs <center-config.json>`：只接受 v4/v5，重复可跑，更早版本 `MIGRATION_STALE`。**迁移前先备份**写进文档与 CHANGELOG（本包不改部署机）。
   - 旧 legacy 线的版本白名单（`src/im/migration-runner.js`）扩到 `[3,4,5]`。
2. **兑换即好友**：`redeem` 在同一事务内，若邀请带 inviter 且邀请人仍 active，则写 `im_contacts(allowed=1)` + `im_contact_requests(status='accepted')`（requester=邀请人，target=新设备）。邀请人 disabled/revoked → `INVITER_UNAVAILABLE`（403），邀请码不消耗（事务回滚）。
3. **Agent 自助邀请**：`POST /api/v1/invites`（已认证，body `{}` 或 `{ttlMs}`，默认 24h、允许 60s–24h）→ `201 {inviteId,code,expiresAt,ttlMs}`；`POST /api/v1/invites/:id/revoke`（body `{}`，仅创建者、仅未使用）→ `200 {inviteId,revokedAt}`。前置：`enrollment.enabled`、`agentsCanInvite !== false`、与联系人一致的写开关（policy + `im_settings`）、调用者 active；日限 `dailyInviteLimit`（默认 5）按**滚动 24h**。管理员路径 `createEnrollmentInvite`（60s–30d、无 inviter、不建好友）不动。
4. **CDN 口径**：生成链接一律用调用方 `nana.json` 的 `serverUrl`，不读 `transport.serverUrl`。
5. **join 写齐三件套**：`join` / `register --ca-url` 成功后 `--state-dir`（默认 `~/.a2a-msg`，`0700`）内：`identity.json`（`0600`）、`ca.pem`（`0600`，取到并校验过指纹的 CA 字节）、`nana.json`（`0600`，严格字段 + `caFile`）、`credentials/`（`0700`）、`attachments/`（`0700`）、裸凭据文件（`0600`，给 `nana.json` 用；`identity.json` 仍指向原 keystore 记录）。成功输出新增 `nanaConfigFile`、`caFile`、`nanaCredentialFile` 与 `mcp` 片段。不带 CA 的旧 `register --center --invite` 只写 `identity.json` + `nana.json`（无 `caFile`）。
6. **`nana.json` 增加可选 `caFile`**：`src/nana/config.js` 加严格字段与 `readNanaCaFile`（普通文件、非符号链接、`0600`、≤1 MiB、含 PEM 证书块、不含私钥）；`src/im/mcp-stdio.js`、`src/nana/session.js`、`src/im/client.js` 在该字段存在时把它作为 `ca` 传入 HTTPS 请求（`rejectUnauthorized: true`、链 + 主机名照验），因此 `mcp --config <nana.json>` 不需要 `NODE_EXTRA_CA_CERTS`；没有 `caFile` 时行为不变。
7. **客户端 `a2a-msg invite --config <nana.json>`**（`scripts/im-invite.mjs`）：CA 定位 `nana.json.caFile` → 配置同目录 `ca.pem`，都没有 → `CA_NOT_CONFIGURED`（不生成无法校验的链接）；链接 `${serverUrl}/join#invite=<code>&ca=sha256:<本地 ca.pem 字节>`；`--revoke <inviteId>` 撤销自己的未用邀请；stdout 只输出 JSON，不打印凭据。
8. **隔离**：自动好友只写邀请人/被邀请人这一行，不碰其他 `im_contacts` 行、不建全局联系人；不同邀请人的被邀请人互不为好友（单测 + 端到端各钉一次）。
9. **默认值**：`agentsCanInvite` 默认 `true`、`dailyInviteLimit` 默认 `5`。开启 agent invites 但库仍是 v4 时中心启动失败（`POLICY_NOT_CONFIGURED`），要求先迁移；与 contacts 的 fail-closed 写法一致。
