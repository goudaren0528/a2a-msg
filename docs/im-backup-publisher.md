# Trusted backup publisher (Lane A)

Use `createTrustedBackupServices({ db, dir, authority })` on a supported private Unix local filesystem. `publisher.publish({ adminContext, approvalId })` is the only supported publication route. The trusted authority must authorize synchronously with literal `true` and bind `publicationActors(adminContext)` to executor and approver actor IDs. Caller-supplied artifact, ID, source, hash or provenance fields are ignored.

The publisher binds source DB identity (`instanceId`, `createdAt`) to a new immutable registry version-2 instance record, then creates a native online backup. The primitive still supports backing up v1 or uninitialized databases, but the publication gate refuses those sources. Before publication, the primitive securely opens the native pending SQLite file, checks its identity and single link, sets mode 0600 through its fd and fsyncs. The publisher requires strict durable output, actual `backup.verify()`, copied identity matching the source and registration, and a fresh source identity check after asynchronous backup. Its private writer repeats manifest, copied identity, hash and real verification checks under the cross-process registry lock, then fsync-publishes an immutable version-2 record. Revocation and cleanup use the same lock.

Failures can leave uncertain disk entries after crash/fsync faults; reconcile before retrying. A copied DB with another identity or corrupt foreign keys cannot be published by this facade. The trusted management process and private filesystem permissions, not cryptographic signatures, form the provenance boundary. Windows strict registry and network filesystems are not certified. Lane C runner wiring and live transaction guards remain separate work.
